# חיפוש קולי במכלול — מודול API לימות המשיח

מודול Node.js ל-Vercel שמפעיל שלוחת `type=api` בימות המשיח:

1. מבקש מהמתקשר להקליט מה לחפש.
2. מוריד את קובץ ה-WAV שנשמר בימות.
3. שולח את ה-WAV למיקרו-שירות התמלול הקיים שלך.
4. מחפש במכלול ומציג עד 5 תוצאות לבחירה בהקשה.
5. שולף את תמצית הערך הנבחר ומקריא אותה באמצעות `id_list_message` + `t-`.

## קבצים

- `api/michlol.js` — endpoint של Vercel וה-state machine.
- `lib/michlolApi.js` — חיפוש ושליפת תמצית דרך MediaWiki API.
- `lib/yemotResponse.js` — בניית תגובות `read` ו-`id_list_message` ופיצול TTS.
- `lib/yemotFiles.js` — הורדת הקלטת WAV מ-DownloadFile.
- `ext.ini` — דוגמת הגדרה לשלוחת `type=api`.
- `package.json` — הגדרת Node.js.

## משתני סביבה ב-Vercel

### חובה

`TRANSCRIBE_URL`

כתובת ה-endpoint הקיים שלך ב-Python שמקבל POST של בייטי WAV ומחזיר JSON בצורה:

```json
{"text":"הטקסט שתומלל"}
```

המודול אינו כולל מנוע תמלול חדש. הוא משתמש בשירות הקיים. הקוד שהועלה לפרויקט המקורי משתמש ב-`recognize_google()` בעברית `he-IL`, ומוסיף 500ms שקט לפני ואחרי האודיו. fileciteturn4file1

`RECORDINGS_FOLDER` (אופציונלי)

ברירת מחדל: `/api_search`.
חייב להיות זהה לתיקייה שבה `ext.ini` שומר את ההקלטה.

`YEMOT_API_KEY` (אופציונלי)

אפשר להגדיר טוקן ברמת Vercel, אבל לפרסום המודול ההמלצה היא להשתמש ב-API KEY ברמת השלוחה באמצעות `api_add_0=YemotApiKey=...`, כדי שכל מערכת תוכל להגדיר את הטוקן שלה.

### אפשרויות

- `RESULT_COUNT` — מספר תוצאות, ברירת מחדל 5, מקסימום 5.
- `TTS_CHUNK_SIZE` — אורך יעד לפיצול TTS, ברירת מחדל 600 תווים.
- `MICHLOL_API_TIMEOUT_MS` — timeout לחיפוש במכלול, ברירת מחדל 10,000ms.
- `YEMOT_DOWNLOAD_TIMEOUT_MS` — timeout להורדת ההקלטה, ברירת מחדל 15,000ms.
- `TRANSCRIBE_TIMEOUT_MS` — timeout לתמלול, ברירת מחדל 15,000ms.
- `RECORDING_PARAM` — ברירת מחדל `SearchRecording`.
- `CHOICE_PARAM` — ברירת מחדל `MichlolChoice`.
- `TOKEN_PARAM` — ברירת מחדל `YemotApiKey`.

## טוקן ימות המשיח — API KEY

המודול מיועד לפרסום ולכן **לא** משתמש במספר מערכת וסיסמה בתצורת ההתקנה.

לפי חומר התיעוד שסופק לפרויקט, ל-Management API קיימים טוקנים קבועים מסוג **API KEY**, המונפקים דרך ממשק "חומת האש". התיעוד מציין שטוקן כזה קבוע, אינו פג תוקף, וניתן להגביל אותו לפי כתובות IP ושירותים.

בגלל שהטוקן עובר כחלק מנתוני שלוחת ה-API, ההגדרה `api_log=no` חשובה במיוחד כדי שלא יישמר בלוג API של ימות. בנוסף מוגדר `api_url_post=yes`, כך שהנתונים נשלחים ב-POST ולא בתוך URL.

## ext.ini

```ini
type=api
api_link=https://YOUR-VERCEL-PROJECT.vercel.app/api/michlol
api_url_post=yes
api_log=no
api_add_0=YemotApiKey=YOUR_API_KEY
```

אין לשים בריפו טוקן אמיתי.

## הקלטה

המודול מחזיר לימות `read` עם סוג `record`, ולא `voice`, כדי שההקלטה תגיע לשירות התמלול החיצוני שלך.

ההגדרה שנוצרת בקוד היא בסגנון:

```text
SearchRecording,,record,/api_search,,no,yes,1,30
```

כלומר: שמירה בתיקייה `/api_search`, ללא תפריט אישור, שמירה בניתוק, מינימום שנייה ומקסימום 30 שניות.

יש לבצע בדיקה טלפונית בפועל שהפרמטר `SearchRecording` שמגיע לשרת אכן מכיל את שם הקובץ או הנתיב הצפוי. הקוד תומך גם בערך שהוא שם קובץ וגם בערך שהוא נתיב מלא.

בשלב הבחירה אין שמירה של רשימת התוצאות ב-DB: המודול מבצע מחדש את התמלול והחיפוש, ואז משתמש במספר שהמתקשר הקיש. כך נשמרת הדרישה ל-state-less ללא מסד נתונים.

## פיצול TTS

`id_list_message` מפריד פריטים בנקודה, וסוג `t-` משתמש במקף כמפריד בין הסוג לטקסט. לכן `lib/yemotResponse.js` מנקה נקודות ומקפים מתוך טקסט לפני ההחזרה ומפצל טקסט ארוך.

**חשוב:** 600 תווים הוא ערך כיול בלבד. אין לקבוע ממנו מגבלה רשמית של ימות. יש לבצע בדיקה טלפונית ולכוונן את `TTS_CHUNK_SIZE` בהתאם לאורך המרבי שעובד בפועל.

## בדיקות חובה לפני פרודקשן

1. ליצור API KEY אמיתי של ימות עם הרשאות מינימליות ככל האפשר.
2. לוודא שה-API KEY מורשה ל-`DownloadFile`.
3. לבצע שיחה ולבדוק שההקלטה נשמרת ב-`/api_search`.
4. לבדוק מה הערך המדויק שמגיע תחת `SearchRecording`.
5. לבדוק שה-WAV שנשלח לשירות התמלול מתקבל בפורמט שהשירות מצפה לו.
6. לבדוק תמלול עברית קצר וארוך.
7. לבדוק חיפוש עם תוצאה אחת, מספר תוצאות וללא תוצאות.
8. לבדוק הקשות 1–5 לבחירת תוצאה.
9. לבדוק בחירה לא חוקית.
10. לבדוק ערך שאין לו extract זמין.
11. לכייל את `TTS_CHUNK_SIZE` בשיחה אמיתית. 600 אינו נתון רשמי.
12. לבדוק עברית, נקודות, מקפים, גרשיים ותווים מיוחדים בתוכן המוחזר.
13. לבדוק timeout/תקלה בשירות התמלול וב-API של המכלול.
14. לוודא שהטוקן אינו מופיע ב-`LogApi.ymgr`, בלוגים של Vercel או בהודעות שגיאה.
15. לבצע שיחה לאחר ניתוק באמצע הקלטה ולבדוק את ההתנהגות של שמירה בניתוק.

## אבטחה

- אין לשמור API KEY אמיתי ב-GitHub.
- אין להדפיס את הטוקן ללוגים.
- אין להשתמש במספר מערכת:סיסמה בגרסה הציבורית של המודול.
- מומלץ ליצור API KEY ייעודי למודול ולהגביל אותו לפי האפשרויות שממשק ימות מאפשר.
- אין להעביר את הטוקן למיקרו-שירות התמלול; הוא נדרש רק להורדת ההקלטה מימות.
